How hash-based file sharing works

When you upload a file, the node computes its SHA-256 hash and stores it at cjp2p/public/<sha256>. The URL you get looks like:

http://127.0.0.1:24255/<sha256>

Because the URL is the hash of the content, it has two useful properties:

  • Self-verifying: any node that serves you the file can be verified by hashing what you received and comparing it to the URL. If the bytes are wrong, the hash won't match — no trust required.
  • Immutable: the same URL will always mean the same bytes, forever. Old links never break and never silently change.

P2P propagation

When a node receives a request for a hash it doesn't have locally, it asks its peers. Any peer that has seen the file can respond. Once a node has the file, it serves it to future requesters — so the file spreads through the network as demand exists.

  • You don't have to stay online. Once any peer has downloaded your file, that peer can serve it.
  • Files are automatically replicated by every node that downloads them.
  • There is no central server. Any node that has the bytes is a server.

For updatable named URLs (same link, new content), see Publish.
