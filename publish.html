What "publish" does

Publishing gives a file a persistent, updatable URL tied to your node's identity. The URL looks like:

http://127.0.0.1:24255/latest/<your-pubkey>/<publish-path>

The publish name is the path the file is served under -- it doesn't have to match the source filename. You might drop myapp-v2.3.tar.gz but publish it as myapp/latest.tar.gz, so that URL stays stable across releases. Subdirectory paths (e.g. tools/index.html) are allowed.

That URL always resolves to your current version of that name. Republish with the same name to update it. Your public key is part of the URL, so no one else can overwrite it.

How it works internally

  • The file is written to cjp2p/origin/<publish-name> on your node.
  • When anyone requests the /latest/ URL, your node hashes the current file and signs a Latest message binding (your-pubkey, publish-name) to that SHA-256, with a sequence number equal to the file's modification time.
  • That signed message propagates to peers. Any peer that has seen it can answer future requests -- even if your node is temporarily offline -- by pointing the requester at the right hash. The actual bytes are served from cjp2p/public/<sha256> and spread peer-to-peer from there.
  • When you republish, the new Latest message has a higher sequence number. Peers prefer the highest they have seen, so the URL automatically tracks the new content.

Publish vs. Upload

Publish (this page) URL: /latest/<key>/<name>
Mutable -- republish to update
Tied to your identity
You control the public name
Upload URL: /b3/<blake3> or /<sha256>
Immutable -- content is the address
Anonymous
Any peer holding the bytes can serve it
